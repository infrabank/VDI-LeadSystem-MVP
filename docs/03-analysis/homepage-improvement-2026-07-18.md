## 1. 현재 홈페이지의 핵심 문제점 (진단 결과)

1. **모든 방문자에게 같은 문장** — 홈이 VDI 담당자·중소기업 담당자·SI 담당자를 한 동선으로
   받았다. 각자 자기 경로를 5초 안에 못 찾음.
2. **VDI 페이지가 기술 항목 나열** — "포함 항목" 리스트만 있고, 운영 담당자가 겪는 증상
   언어("인증서 교체 후 접속 오류")가 없어 "내 문제"로 인식되지 않음.
3. **의뢰 방식 불명확** — 단발/프로젝트/정기/SI 지원 유형 구분과 견적 산정 기준이 없어 문의
   장벽이 높았음.
4. **문의 폼이 단일 구조** — 14개 관심영역 칩 + VDI 중심 안내로, 유지보수·SI 고객에게 맞지
   않는 언어. 서버 API가 `research`·`si-partner` 기관유형을 조용히 버리는 버그도 있었음.
5. ~~파트너 표기 오인 소지~~ → **해당 없음 확인** — 2026-07-18 대표 확인 결과
   Citrix·VMware·Omnissa·Acronis·Vinchin 5개 벤더 모두 공식 파트너. "공식 파트너" 통합
   표기로 정리 (구분 표기는 도입 후 철회).
6. **전 페이지 타이틀 중복** — 루트 템플릿이 `| Myloket`을 붙이는데 페이지들이 또 하드코딩해
   `... | Myloket | Myloket`으로 렌더 (검색 결과 노출 품질 저하). 20여 페이지 해당.
7. **불필요한 영어 섹션명** — Business Areas, Field Issues, Track Record 등.
8. **개조체 문장** — 서비스 페이지 hero에 "~점검함", "~남김" 등 어색한 개조체.
9. **CTA 문구 획일** — "문의하기/점검 문의하기"로 통일되어 클릭 이유가 불명확.
10. **1인기업 우려에 대한 명시적 답 부재** — RACI 분담표는 있었으나 "대표 부재 시?", "상주
    필요 시?" 같은 질문에 직접 답하지 않았음.

## 2. 유지한 강점

- 검증 가능한 사실만 쓰는 카피 (인증번호 공개, 익명 표기 원칙 문구)
- 수행 실적 섹션(카테고리별 기관 수 + 대표 수행 사례), RACI 책임 분담표
- 문의 prefill(`?source=&interest=&subject=`), 리드 upsert 파이프라인
- 모바일 하단 전화 바, 법적 표기, 개인정보 동의 구조 (필수/선택 분리)
- 진단 도구 6종·insights·practices 콘텐츠 자산 (7/18 오전 GNB 노출 완료)

## 3~13. 적용 완료 내역 (실제 코드 반영)

### 메인 페이지 (§2, §9)
- Hero 직후 **방문자 3경로 분기 블록** 신설: VDI 장애·기술지원 / 전산 통합 유지보수 / SI
  프로젝트 협업. 각 카드에 대상 고객, 핵심 증상, 목적별 CTA("VDI 장애 원인 상담" 등),
  클릭 후 일어나는 일 설명 포함. — `src/app/(public)/page.tsx`
- 영어 eyebrow 전부 한국어화 (Business Areas→사업 영역 등), hero 포지셔닝 라인 한국어화.
- CTA 구체화: "점검 문의하기"→"현재 증상 상담하기", "서버·네트워크 점검 문의".

### VDI 기술지원 페이지 (§3, §4, §11)
- **증상 중심 12개 장애 시나리오** 아코디언: 각각 진단 범위 / 자주 있는 원인 / 조치·산출물 /
  문의 시 필요한 최소 정보 구조. (간헐 접속 실패, UAG 외부 접속 불가, 인증서 교체 후 오류,
  로그인 지연, FSLogix 미로드, VDA 미등록, IC·MCS·PVS 배포 실패, vCenter 업그레이드 연동,
  스토리지 병목, 라이선스·정책 변경, 구축업체 철수, 업체 간 책임 떠넘김)
- **E2E 분석 흐름** 시각화: 사용자 단말→DNS·인증서→게이트웨이→브로커→VDA→프로파일→
  vCenter·ESXi→스토리지·네트워크.
- **지원 유형 4종 카드** (단발/프로젝트/정기/SI): 적합 고객, 범위, 원격·방문 방식, 결과물,
  "계약 없이 단발 의뢰 가능" 명시. 진행 순서(접수→1영업일 회신→견적 협의→지원→보고) 명시.
- **견적 산정 기준 공개** (가격 임의 제시 없음): 제품 종류, 규모, 긴급도, 원격/방문,
  로그·구성도 보유, 보고서 범위.
- FAQ 8개로 확장 — "VDA 등록 오류", "UAG 접속 오류", "FSLogix 로그인 지연" 등 검색 질의
  대응 (FAQPage JSON-LD 자동 반영). 메타 타이틀·설명도 검색어 기준 재작성.

### 전산 유지보수·백업 페이지 (§7 일부)
- CTA 목적별 교체: "전산환경 점검 문의"→"월간 유지보수 상담", "백업·보안 점검 문의"→
  "백업 복구 가능성 점검". 개조체 문장("~점검함/~남김/~작업함") 경어체 정리.
- 타이틀에 지역 검색어 반영: "중소기업 전산 통합 유지보수 — 세종·대전·충청 IT 기술지원".

### 수행 사례 (§5) — 구조만 적용, 내용은 실자료 필요
- 사례 데이터는 **만들지 않았다** (§13 준수). 사례 콘텐츠 구조(고객 유형/규모/제품/문제/역할/
  작업/결과/산출물)는 아래 "추가 확보 자료" 참고. CMS(admin > 콘텐츠, type=case)로 발행하면
  /case-studies에 자동 노출되는 파이프라인은 이미 동작 중.

### 대표·회사 소개 (§6)
- about에 **"1인 전문기업, 자주 받는 질문"** 5문답 신설: 대표 부재 시 대응(1영업일 회신 기준
  + 우선순위 원칙, 상시 즉시 출동 아님을 정직하게 명시), 상주 필요 시(컨소시엄 구조), 대규모
  구축(협력사 분담), 작업 기록·환경 정보 관리, 영업=기술 동일인.
- 영어 eyebrow 한국어화 (Our Mission→미션, Founder→대표 엔지니어 등).

### 문의 페이지·폼 (§8)
- **문의 유형 3종 선택 UI** (VDI 장애·기술지원 / 전산 통합 유지보수 / SI 프로젝트 협업).
  URL param(`?type=`, `?interest=`)으로 자동 선택.
- 유형별 상세 필드 (전부 선택 항목 — 최소 정보만 필수, 세부는 통화 확인 방식):
  - VDI: 제품·버전, 규모, 발생 시점, 긴급도, 원격 접속 가능 여부
  - 유지보수: 위치, 임직원·PC 수, 장비 현황, 기존 업체 유무, 방문 희망
  - SI: 사업명, 진행 단계, 필요 기술 영역, 예상 일정, 상주·비상주
- 상세 필드는 메시지에 구조화 블록으로 첨부되어 기존 API·DB 스키마 무변경.
- 14개 관심영역 칩 제거 (유형에서 자동 도출) → 입력 부담 대폭 감소.
- 로그·스크린샷 첨부는 "회신 메일에 답장으로 첨부" 안내로 대체 (파일 업로드는 보류 항목).
- **버그 수정**: `/api/inquiries`의 기관유형 화이트리스트에 `research`·`si-partner` 누락 →
  추가. 제출 버튼 라벨 유형별 변경, "영업 전화 돌리지 않습니다" 문구 추가.

### 신뢰 요소 (§10)
- **파트너 표기 확인·정리** — 대표 확인 결과 5개 벤더 모두 공식 파트너로 확인되어
  "공식 파트너" 통합 라벨로 표기 (홈 스트립·홈 파트너십 섹션·about·certifications).
  `Partnership.official` 필드는 유지 — 향후 비공식 벤더 추가 시 구분 표기용.
- **타이틀 중복 제거** — 20개 페이지의 `| Myloket` 하드코딩 제거 (루트 템플릿이 1회만 부착).
- 영어 섹션명 한국어화 (홈·about·서비스 3페이지·contact).
- 모바일 전화 바 라벨 "점검 문의"→"상담 문의" (문의 유형 선택 페이지로 연결).

### 검색 유입 (§11)
- vdi-support: 증상 섹션 + FAQ가 "Citrix VDA 등록 오류", "Horizon UAG 접속 오류",
  "FSLogix 로그인 지연", "인증서 교체", "vCenter 업그레이드" 질의에 페이지 내 직접 답변.
- it-maintenance 타이틀에 "세종·대전·충청" (areaServed 사실 기반).
- 나머지 검색어(개별 오류 케이스 심화)는 insights 콘텐츠로 — 중기 계획 참고.

## 15. 우선순위별 실행 계획

- **즉시 수정 (완료)**: 타이틀 중복, 파트너 표기 분리, API 기관유형 버그, CTA 구체화,
  3경로 분기, 문의 폼 3유형, 개조체 정리 — 이번 커밋에 전부 반영.

  보고서 샘플 캡처 삽입.
- **중기**: 검색어별 insights 콘텐츠(오류 케이스 해설 → 해당 증상 섹션으로 내부링크),
