## 4. 의도적 미평가 통제 카테고리 (244개)

### 4.1 v3/v4 입력 필드 부재로 인한 미평가 (재도입 후보)

`risk-assessment-v4.ts:12-18` SKIPPED RULES 주석에 명시:

| 도메인 | 미평가 사유 | 재도입에 필요한 입력 |
|---|---|---|
| RA-01 | 세션 타임아웃 | `session_timeout_min` 필드 |
| IN-01 | 패치 관리 | `patch_management` 필드 |
| AC-02·03 | 모니터링·SIEM | `monitoring_level`, `siem_level` |
| DU-01 | 백업 암호화 | `backup_encrypted` |
| 추가 | DLP, encryption_at_rest, audit_log, encryption_key, identity_provider | 5개 필드 |

→ **v5 입력 확장 시 약 10~15개 통제 추가 평가 가능** (총 40~45개 / 274 = 15~16%)

### 4.2 자가진단 도구 범위 외 통제 (구조적으로 미평가)

다음은 진단 도구가 아니라 **현장 감사·문서 검토**로만 평가 가능:

- **LP (정보보호 정책, 13개)**: 정책 문서 존재·승인 절차·교육 — 사이트 폼으로 평가 불가
- **IV (자산 관리, 5개)**: 자산 인벤토리·라이프사이클 — 별도 시스템 데이터 필요
- **IM (인적 보안, 5개)**: 채용·해지·교육 — HR 데이터
- **AU (감사·로깅, 10개)**: 로그 보존·검토·SIEM 연동 — 운영 환경 직접 점검
- **LI (라이프사이클, 12개)**: SDLC·릴리스·취약점 — 개발 프로세스
- **MD (매체 폐기, 13개)**: 물리 매체 폐기 절차 — 현장 감사
- **DV (변경 관리, 14개)**: 형상 관리·CMDB — 별도 시스템
- **EK·EA (암호, 9+3)**: 암호 키 관리 — 별도 KMS
- **SN (공급망, 12개)**: 공급망 보안 — 계약·실사 문서

→ **이 영역(약 90~100개 통제)은 자가진단 도구로는 평가 불가** — 정직한 한계.

### 4.3 모델별 emphasis_controls (점수 영향 없음, 권고로만 노출)

`models.json` 에 모델 3·8·10·기타별 강조 통제 리스트:
- 모델 3 (SaaS 협업): 약 N개 통제 권고
- 모델 8 (통합문서): 약 N개 통제 권고
- 모델 10 (무선): 약 N개 통제 권고

이들은 `n2sf_compliance.recommended_controls` 필드로 리포트에 노출되지만 **점수에는 반영 안 함** (안전한 default — 통제 ID 인용만 됨).

## 5. 마케팅 카피 가이드라인 (Round 2 권장)

### 5.1 사용 금지 표현
- ❌ "274개 보안통제 매핑" — 모호. 카탈로그 검색인지 룰 평가인지 구분 안 됨
- ❌ "N²SF 274 통제 정렬 진단" — 정렬되지 않은 244개를 무시
- ❌ "274 통제 기반 자가 진단" — 30개만 룰 평가됨

### 5.2 권장 표현
- ✅ "N²SF 1.0 부록1 274 통제 카탈로그를 참조한 자가 진단 (직접 평가 30개 + 모델별 권고)"
- ✅ "VDI 환경 핵심 30개 N²SF 통제 룰 평가 + 모델 3·8·10 권고 통제 매핑"
- ✅ "N²SF 정렬도 자가 측정 도구 — 평가 가능한 30개 통제 + 카탈로그 검색"

### 5.3 영업·RFP 대응 시
경쟁사가 "274 마케팅 vs 엔진 0회"로 공격하면 본 카탈로그를 제출:
> "Myloket 진단 엔진은 N²SF 1.0 부록1 274 통제 중 자가진단 도구로 평가 가능한 30개를 룰 기반으로 평가하고, 나머지 244개는 모델별 권고·카탈로그 검색·NDA 후 정식 진단 단계에서 다룹니다. 자가진단 도구의 한계와 정식 진단의 가치를 명확히 구분합니다."

→ 공격 카드를 "정직한 한계 인정 + 단계별 솔루션"으로 전환.

## 6. v5 진단 엔진 로드맵 (점진 커버리지 확장)

### Phase 1 (1개월) — 입력 필드 5개 추가
- session_timeout_min (RA-01)
- patch_management (IN-01)
- monitoring_level (AC-02)
- siem_level (AC-03)
- backup_encrypted (DU-01)

→ 추가 5~6개 통제 평가 가능 (35~36 / 274 = 13%)

### Phase 2 (2~3개월) — 입력 필드 5개 추가
- DLP (DU-X)
- encryption_at_rest (EK-X)
- audit_log_retention_days (AU-1)
- encryption_key_management (EK-1)
- identity_provider (MA-3)

→ 추가 7~10개 통제 (45 / 274 = 16%)

### Phase 3 (6개월) — 정식 진단 (NDA 트랙) 통합
- 자가진단(30~45개) + NDA 후 컨설턴트 정식 진단(추가 100~150개)
- 정식 진단은 자가진단 결과 기반으로 컨설턴트가 보충 인터뷰·문서 검토

## 7. 결론

> **N²SF 274 매핑은 마케팅이 아니라 정직한 단계별 카탈로그다.**
> 자가진단 30개 → 입력 확장 45개 → NDA 정식 진단 150~200개 → 현장 감사 274개 풀커버.
