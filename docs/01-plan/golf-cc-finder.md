# 골프CC 파인더 — 전국 골프장 정보·공략 조회 서비스 기획서

> 작성: 2026-07-12 · 상태: 기획 초안 (v0.1)
> 워킹 타이틀: **골프CC 파인더** (가칭 — 도메인 확보 후 확정)

---

## 1. 한 줄 정의

전국 골프장(회원제 CC·대중형·퍼블릭)의 **위치·연락처·기본 정보·특이사항·홀별 공략팁**을
예약 없이, 로그인 없이, 검색으로 바로 찾아볼 수 있는 **골프장 정보 디렉터리 + 공략 아카이브**.

**핵심 흐름** (VDI-LeadSystem과 동일 패턴):
골프장 정보 페이지 발행 → 검색 유입 ("○○CC 공략", "○○CC 그린피", "○○CC 전화번호")
→ 상세 페이지 + 공략팁 → 재방문·구독·제휴 수익

## 2. 왜 하는가 — 문제 정의

| 지금 골퍼가 겪는 문제 | 현재의 대안 | 한계 |
|---|---|---|
| "이번 주 ○○CC 처음 가는데 어떤 코스지?" | 스마트스코어·김캐디 앱 | 앱 설치·로그인 필수, 웹 검색에 안 잡힘 |
| "○○CC 전화번호·오시는 길" | 네이버 지도, 골프장 공식 홈페이지 | 골프장 홈페이지 품질 편차 큼, 정보 흩어짐 |
| "화이트 티 기준 몇 미터? 카트 필수? 캐디 선택제?" | 블로그 후기 검색 | 오래된 글·광고 글 섞여 신뢰 어려움 |
| "3번 홀 도그레그 어떻게 쳐야 하지?" | 유튜브·블로그 개별 검색 | 골프장별로 정리된 곳이 없음 |

**갭**: 골프장 "예약"(XGOLF·카카오골프·똑캐디)과 "스코어"(스마트스코어·김캐디) 시장은 포화지만,
**로그인 없는 웹 기반 골프장 정보·공략 검색**은 비어 있다. 검색엔진(구글·네이버)과
AI 검색(ChatGPT·클로드 등)이 인용할 수 있는 구조화된 골프장 데이터 소스가 없다는 점이 기회다.

## 3. 경쟁·기존 서비스 분석

| 서비스 | 강점 | 우리와의 차이 |
|---|---|---|
| 스마트스코어 | 골프장별 난이도·평점·홀별 공략·드론영상, 430여 개 제휴 ([레저신문](http://www.golftimes.co.kr/news/articleView.html?idxno=135801)) | 앱 중심·로그인 필수. 웹 SEO 노출 약함. 유료화 반감 존재 |
| 김캐디 | 18Birdies 제휴로 야디지·스코어 강화 ([테크M](https://www.techm.kr/news/articleView.html?idxno=128999)) | 스크린골프·레슨 예약 중심. 필드 골프장 정보는 보조 |
| XGOLF·카카오골프예약 | 부킹·조인 | 예약 커머스. 정보·공략 콘텐츠 없음 |
| 네이버 지도/플레이스 | 위치·전화 | 골프 특화 필드(홀·티 거리·공략) 없음 |
| 개인 블로그 | 생생한 후기 | 골프장 단위로 체계화 안 됨, 최신성 보장 없음 |

**포지셔닝**: "골프장의 나무위키 + 공략 가이드북". 예약·스코어와 경쟁하지 않고
**정보 검색 진입점**을 선점 → 예약은 제휴 링크로 넘긴다(수익화 §9).

## 4. 타깃 사용자

1. **원정 골퍼** (1차) — 처음 가는 골프장을 라운드 1~3일 전 검색. "코스 특징·공략·주의사항"이 필요.
2. **총무 골퍼** — 모임 장소 선정. 위치·그린피·단체 수용 여부·연락처 비교.
3. **초중급 골퍼** — 난이도·캐디/카트 정책·티박스 거리로 "내 수준에 맞는 곳" 탐색.

## 5. 데이터 전략 (기획의 성패를 가르는 부분)

### 5-1. 베이스 데이터 — 공공데이터 (무료·합법·전수)

| 소스 | 내용 | 용도 |
|---|---|---|
| [문화체육관광부 전국 골프장 현황](https://www.data.go.kr/data/15118920/fileData.do) | 업소명·대표자·소재지·총면적·홀수·세부종류(회원제/대중형) | 마스터 목록 시드 (~500여 개) |
| [행정안전부(LOCALDATA) 골프장업 인허가](https://www.data.go.kr/data/15045080/fileData.do) | 인허가일자·영업상태·소재지·좌표 | 영업/폐업 상태 검증, 개장연도 |
| 카카오 로컬 API | 좌표·전화번호·도로명주소 | 연락처·지도 표시 보강 |

→ 이 3개 교차만으로 **"전국 전수 + 위치 + 연락처 + 영업상태"**는 자동 파이프라인으로 확보 가능.
분기 1회 갱신 배치로 폐업·신규 반영.

### 5-2. 프로필 데이터 — 반자동 수집 + 검수

홀수·파·전장(티별 거리)·잔디 종류·캐디/카트 정책·부대시설·그린피 범위:
- 골프장 공식 홈페이지 기재 내용을 **사람이 확인하고 입력** (Admin CMS)
- 출처 URL·확인일을 필드로 저장 → 페이지에 "최종 확인일" 표기 (신뢰의 근거)
- 그린피는 변동이 크므로 **"범위 + 확인일"**로만 표기하고 정확한 요금은 골프장 링크로 위임

### 5-3. 공략팁·특이사항 — 콘텐츠 자산 (차별화 핵심)

| 단계 | 방법 | 비고 |
|---|---|---|
| 시드 | 스코어카드·코스 레이아웃 기반 에디토리얼 작성 (홀별 파·거리·해저드 → 공략 포인트) | AI 초안 + 유경험자 검수. **근거 없는 팁 금지** |
| 성장 | 라운드 경험자 UGC 제보 폼 ("이 홀 팁 남기기") → 검수 후 게시 | 채택 시 닉네임 크레딧 |
| 심화 | 지역 골프장 캐디·프로 인터뷰 시리즈 | 콘텐츠 마케팅 겸용 |

**특이사항 필드 예시**: 산악/평지, 블라인드 홀 수, 그린 난이도 평판, 카트 도로 상태,
겨울 휴장 여부, 안개 잦음, 진입로 협소, 식당 평판, 노캐디 가능 여부.

### 5-4. 하지 않는 것 (법적·품질 리스크 차단)

- 타 플랫폼(스마트스코어 등) 데이터 스크레이핑 **금지** — 약관 위반·DB권 침해 리스크
- 실시간 예약·잔여 티타임 표시 안 함 (제휴 없이는 부정확)
- 검증 불가한 평점·순위 자체 산정 안 함 (초기에는 사실 나열 원칙 — 회사 도메인 룰과 동일)

## 6. 핵심 기능

### MVP (Phase 1)

1. **골프장 검색·필터** — 지역(시도/시군구), 유형(회원제/대중형/퍼블릭), 홀수, 이름 검색(FTS)
2. **골프장 상세 페이지** (SEO 단위, `/golf/[slug]`)
   - 기본: 위치(지도)·주소·전화·홈페이지·홀수·파·전장·개장연도·운영형태
   - 특이사항: 코스 성격·정책·시설 (§5-3 필드)
   - 공략: 코스별 요약 공략 + 홀별 팁 (있는 곳부터 점진 확충)
   - "최종 확인일" + 출처 표기
3. **지도 탐색** — 전국 지도에서 마커 브라우징, 현 위치 주변 골프장
4. **정보 수정 제보 폼** — 로그인 없이 제출 → Admin 검수 큐
5. **Admin CMS** — 골프장 CRUD·공략 에디터·제보 검수 (기존 admin 패턴 재사용)

### Phase 2 (검증 후)

- 홀별 공략 UGC 시스템 (간이 계정 or 소셜 로그인)
- 골프장 비교 (2~3곳 나란히)
- "다가오는 라운드" 브리핑: 골프장 + 당일 날씨(기상청 API) 요약 페이지
- 뉴스레터: 지역별 신규 개장·리뉴얼 소식

### 명시적 보류

- 예약/결제, 스코어 기록, 커뮤니티 게시판 (기존 강자 영역 — 진입 안 함)

## 7. 데이터 모델 (Supabase)

```
golf_courses          -- 마스터
  id, slug, name, name_en, type(회원제/대중형/퍼블릭),
  sido, sigungu, address, lat, lng,
  phone, website, holes, par, opened_year,
  status(operating/closed), source_refs jsonb,
  verified_at, created_at, updated_at, fts(tsvector)

course_profiles       -- 프로필(1:1, 검수 입력)
  course_id FK, green_fee_range, caddie_policy, cart_policy,
  grass_type, terrain, facilities jsonb, notables jsonb(특이사항 배열),
  season_note, verified_at, source_url

course_layouts        -- 코스(1:N — IN/OUT/레이크 등)
  id, course_id FK, name, holes, par, length_champion, length_regular

hole_tips             -- 홀별 공략(1:N)
  id, layout_id FK, hole_no, par, distance_m,
  tip_md, hazard_note, difficulty(1~5),
  author_type(editorial/ugc), status(draft/published), credited_to

tip_submissions       -- UGC 제보 큐
  id, course_id, hole_no, body, nickname, contact, status(pending/approved/rejected)

corrections           -- 정보 수정 제보
  id, course_id, field, suggestion, evidence_url, status
```

RLS: published만 public 노출, 제보 테이블은 insert-only(익명) + admin 전체 — 기존 패턴 그대로.

## 8. 기술 스택 — 기존 자산 재사용

VDI-LeadSystem-MVP의 아키텍처를 그대로 복제(별도 repo·별도 Supabase 프로젝트):

- Next.js 16 App Router + TypeScript + Tailwind v4 — 정적 생성(SSG/ISR)으로 500여 상세 페이지 프리렌더
- Supabase (PostgreSQL + FTS + RLS + Auth) — 검색·Admin 인증 기존 코드 이식
- 지도: 카카오맵 JS SDK (국내 정확도·무료 쿼터)
- SEO/AEO: 페이지별 JSON-LD (`GolfCourse` schema.org 타입 존재!) + FAQ 구조화 — AI 검색 인용 최적화
- 데이터 파이프라인: 공공데이터 CSV/API → 정제 스크립트(Node) → upsert 배치 (분기 1회 + 수동 트리거)

**신규 개발 필요분은 사실상 "골프 도메인 스키마 + 지도 UI + 데이터 파이프라인"뿐** — 나머지는 검증된 코드.

## 9. 수익 모델 (순서대로 검증)

1. **제휴 아웃링크** — 상세 페이지 "예약하기" → XGOLF·카카오골프 등 제휴/어필리에이트 링크 (CPA)
2. **디스플레이 광고** — 트래픽 확보 후 애드센스/쿠팡파트너스 (골프용품)
3. **골프장 대상 B2B** — "정보 공식 인증·업데이트 권한" 유료 플랜 (플레이스 클레임 모델)
4. (장기) 프리미엄 공략 콘텐츠 구독

초기 6개월은 수익보다 **인덱싱·트래픽·데이터 완성도**에 집중.

## 10. 법적·운영 유의사항

- 공공데이터: 이용허락범위 확인 후 출처 표기 (대부분 자유이용)
- 골프장 명칭·로고: 명칭은 사실 표기로 사용 가능, 로고·코스맵 이미지는 무단 게재 금지 (직접 제작한 개념도로 대체)
- UGC 팁: 게시 전 검수 필수 (비방·허위 필터), 이용약관에 저작권 귀속·삭제 정책 명시
- 개인정보: 제보 폼 연락처는 선택 항목 + 검수 후 파기 원칙
- 콘텐츠 톤: 회사 도메인 룰 준용 — 과장 표현·검증 불가 수치 금지, "최종 확인일" 기반 정직한 표기
